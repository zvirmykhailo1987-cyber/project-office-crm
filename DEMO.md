# Project Office CRM — demo guide

Everything you see is synthetic (generated by `app/seed_demo.py`). Start the demo with
`docker compose up --build` and open <http://localhost:8030>.

## Accounts

Each person has an individual account. In demo mode the sign-in page lists these demo accounts
and fills the form with one click; in production it lists nothing.

| Login | Password | Role | Can do |
|---|---|---|---|
| `marko` | `marko-demo-2026` | Software & analytics | administration, data service, delete, send, edit any document |
| `bohdan` | `bohdan-demo-2026` | Investors & negotiations | **approves** work (and is not an administrator), edits any document |
| `oksana` | `oksana-demo-2026` | Communities & companies | directory, deals, tasks |
| `halyna` | `halyna-demo-2026` | Requests & correspondence | send letters, outgoing register |

These passwords exist only in demo mode; production starts with a single bootstrap admin whose
password must be provided through the environment.

## 3-minute walkthrough

1. **Sign in as `marko`.** *My day* shows what needs attention for this role and what changed
   since the last visit. Switch theme (moon icon) and language (profile menu → Українська).
2. **Sites → any biogas site.** The score is decomposed into components with weights and the
   source of each raw value; missing data is shown as "no data", not as zero.
3. **Pipelines → Bioenergy.** Drag a deal to a later stage: the stage **gate** refuses the move
   when a required document is missing (or not yet signed off), and says what exactly is missing.
4. **Directory → search** for "Valley": full-text search over organisations and people.
5. **Documents → a teaser → submit for approval.** Sign out, sign in as `bohdan`, open
   *Approval*: approve or return for rework (a comment is mandatory). Try approving your own
   submission as `bohdan` — the system will not allow the author to approve their own work.
6. **Tasks.** Assign a task to a colleague; the assignee accepts it or declines with a reason.
7. **Map.** Filter sites by capacity and suitability; share the current view as a link.
8. **Security, visible from the browser:** response headers carry a strict CSP with a per-request
   nonce; five wrong passwords for the same login from the same client lock that pair for 15 minutes; "Sign out everywhere"
   revokes every session of the account.

## Shared demo accounts

The demo accounts are shared by every visitor, so in demo mode nothing can take them away from
the next one: there is no password, login or role editing in the web interface at all, "Sign out
everywhere" is refused with a clear message (it would sign out every other visitor), and a run of
wrong passwords only locks that client (per IP and per IP + login, 15 minutes) — never the account
for everyone. The public demo resets every night at 04:00 CET; a banner says so on every screen.

docker compose down -v && docker compose up --build
